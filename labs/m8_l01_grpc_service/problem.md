# M8-L01 · In-Process gRPC Service & Deadlines

## Problem

In microservices architectures, services communicate via Protocol Buffers over HTTP/2 using gRPC.
Proper gRPC servicers must:
1. Adhere to typed request/response contracts generated by `protoc`.
2. Map domain errors (e.g. key not found) to canonical `grpc.StatusCode`s using `context.abort()`.
3. Respect client deadlines (`timeout=...`), terminating work when remaining budget is expired.
4. Safely handle concurrent requests dispatched across the server's `ThreadPoolExecutor` worker threads.

In this lab, you will implement `KeyValueServicer` backed by an in-process gRPC test rig.

### Required API

| Member | Semantics |
|:---|:---|
| `KeyValueServicer` | Inherits from `kv_pb2_grpc.KeyValueServiceServicer` |
| `Put(request, context)` | Stores key/value pair; returns `PutResponse(success=True)` |
| `Get(request, context)` | Returns `GetResponse(key=..., value=...)`; aborts with `StatusCode.NOT_FOUND` if missing |

## The C++ Mental Model

In [reference.cpp](./reference.cpp), C++ implements `KeyValueService::Service` overriding
`grpc::Status Get(grpc::ServerContext* ctx, const GetRequest* req, GetResponse* resp)`.
Errors return `grpc::Status(grpc::StatusCode::NOT_FOUND, "...")`.

## The Naive Translation

In [naive.py](./naive.py), a developer returning from C++ or web development returns an empty response
`GetResponse(key=request.key, value="")` on missing keys instead of raising an error.
This forces clients to parse response bodies for errors and breaks standard gRPC retry policies,
interceptors, and status-code telemetry.

## Your Task

Refactor [solution.py](./solution.py) to use `context.abort(grpc.StatusCode.NOT_FOUND, ...)`
and synchronize internal state across worker threads.
